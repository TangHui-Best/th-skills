## 1. 选题方法论

### 选题交集模型

面向传播型选题，可以寻找专业领域、读者兴趣与时间节点的交集。技术解析也可以来自长期存在的设计困惑，不要求追逐热点。

光是专业，可能曲高和寡。光是读者兴趣，可能流于肤浅。光是蹭热点，可能昙花一现。三者结合才能找到最精准的引爆点。

### 选题来源

**X（Twitter）**：每日搜索"AI"关键词，抓一手资讯，关注AI博主和公司动态
**Reddit**：r/artificial、r/ChatGPT、r/singularity、r/ClaudeAI等（100+upvote算比较火）
**小红书**：大众舆论场里AI的话题焦点，重点关注评论区
**即刻**：AI博主、产品创意、行业洞察
**微博/抖音/B站**：热搜话题，至少两三个平台同时火才算真正"破圈"
**读者社群**：群友的难点、痛点、经常出现的需求，监测"有没有"、"推荐"等关键词

### HKR质检法

评估传播或叙事型选题时，可以从三个角度寻找入口：
- **H (Happy)** 足够有趣、有悬念？标题和开头能让人好奇想点开？
- **K (Knowledge)** 有信息量？看完能学到新东西？
- **R (Resonance)** 能戳中情绪？让人"对对对我也这么想"？

这些角度用于发散，不设置通用及格数量。技术文章的知识增量与工程相关性可以独立成立，不必制造悬念或情绪共鸣。

### 角色代入法（发散思考）

审视选题时代入不同角色：
- "一个很忙的普通用户"：能帮我省时间/解决具体麻烦吗？
- "一个爱玩的朋友"：够有趣吗？能让我产生"卧槽还能这样？"的惊叹？
- "一个焦虑的学习者"：能让我学到新东西、有新角度吗？

## 2. 选题分类与案例

### 按业务类型

**大模型技术**（大模型、算法、Agent、编程）
- 新模型/新工具发布的第一手解读
- 亲手做一件和AI相关的荒诞实验（污染测试、离谱服务实测）
- 用AI自动化一件具体的日常琐事

**AIGC艺术**（AI设计、视频、音乐、数字人、玩法创意）
- 火爆玩法的保姆级教程
- 新AIGC工具的技巧总结
- 现象级AI内容背后的制作拆解

**泛互联网文化**（深度访谈、现象故事、观点解读、政策解读）
- 从一个魔幻的消费/平台现象看社会
- 用数据分析揭示一个群体困境
- 网络亚文化现象解读

### 按内容类型

**产品评测+推荐**：实测体验为主，有明确好恶判断
**玩法+教程分享**：手把手教读者操作，核心是Prompt和步骤
**现象访谈类**：互联网现象解读、人物专访故事
**认知观点**：对事件的深度分析、论文分享
**AI整活**：自己动手做好玩的东西，展示AI的可能性

### 按写作原型（从范本作者的最佳文章中提炼）

**调查实验型**
亲自下场做一件事，边做边报道发现。最能建立信任感和叙事张力。
- 低价买一个爆款服务实测 → 过程层层反转
- 亲手污染AI的数据源 → 注册小号、发假内容、一步步观察后果
- 花钱买一项上门服务 → 完整体验并报道流程
写法核心：过程叙事 + 层层发现 + 每一步都带真实反应

**产品体验型**
拿到产品实际使用，带着读者一起体验。不是评测报告，是"跟我一起玩"。
- 新Agent产品 → 从初始设置开始，逐个演示功能
- 新创作模型 → 按玩法分类，每个玩法配真实case
写法核心：场景驱动 + 自己的真实感受 + 跟其他产品的自然对比

**现象解读型**
观察到一个有趣的现象，然后层层深入分析。
- 刷屏图片 → 追问为什么这么火 → 连接到集体记忆 → 人生叙事需求
- 模型集体翻车 → 逐个测试 → 找到论文 → 心理学解释 → 哲学感悟
写法核心：好奇心驱动 → 研究 → 知识掉落 → 哲学升维

**工具分享型**
分享工具/Prompt 时，先说明解决的具体问题、适用条件与依据。有真实使用经历时可以采用故事入口；没有经历时直接解释，不强制用个人故事包裹。
- 一个Prompt工具 → 从身边人的真实困扰聊起 → 对关键词的思考 → 工具展示 → 自己的测试结果
写法核心：个人故事铺垫 → 自然引出工具 → 自己的使用过程 → 效果展示

## 3. 内容节奏

阅读推进来自新问题、证据、状态变化或选择条件的引入，不来自高频重复中心结论。段落与章节的承接应说明为什么当前需要这部分内容；不能用「接下来」「回到主线」掩盖结构缺口。

叙事观点可以围绕真实经历安排节奏变化，技术文章则优先沿理解依赖、系统关系或设计选择推进。插入案例后，应解释它怎样支持当前判断；只有确实发生话题转移且需要定位时，才使用简短回扣句，不设置频次要求。

结构性阅读问题使用对应模式的组织与检查方法解决，不靠增加过渡句、情绪或排版强调修补。

## 4. 创意案例工作法

### 三类锚点

**热点锚点**：当下最火的电影、电视剧、社会事件、网络热梗——流量最大公约数
**痛点锚点**：用户最高频、最头疼的问题——实用价值
**炫技点锚点**：AI工具本身最颠覆的核心功能——技术惊叹

### 有真实实践材料时，可组织成微型故事

1. 亮出"挑战"：想解决什么问题？
2. 展示"脑洞"：想到了什么骚操作？
3. 秀出"过程"：怎么一步步实现的？（截图、核心Prompt）
4. 引爆"结果"：最终那个让人"卧槽"的作品

叙事或体验案例可以追求观赏性；技术案例是否保留，取决于它能补足哪条解释或证据，而不是作者是否兴奋。不为故事效果编造过程或结果；示意案例需明确标示，不作为实测证明。
